新测试文件移出仓库留档（未删），复验 268 / 256 / 306 全绿。

### 四条硬规矩
1. **同一仓库同一时刻只允许一个写入者。** 派新单之前必须先确认上一单已终止；
   确认口径 = `list_agents` 看状态 **+** `ps` 看有没有残留进程，两者都过才算死。
   **一次报错不等于进程死了**（本次实证：报 429 后仍在写文件）。
2. **子代理报"失败/额度耗尽"即视为停手指令**，不许它继续写；
   派遣词里写死："遇到 429 立即停止写操作并回报已完成到哪一步"。
3. **脏工作树不得当作进度**。每次接手前先 `git status --porcelain`；
   发现非本人留下的改动，先取证（HEAD、改动清单、回归数字）再决定回滚/接管，
   并且**永远先测既有闸有没有被带崩**——崩了就是回归，不是"进行中"。
4. 留档动作只用 `mv`（移到仓库外），**不用 `git clean -fd`**（未跟踪文件里可能有物证，
   也可能有他人未提交实现，AGENTS.md 已记过同类损失）；`git checkout -- <显式文件>` 只点名要回滚的文件。

## 14. 两条新纪律（2026-11-17，均来自实付学费）

### 14.1 运行身份漂移：root 写字、node 持有仓库
本机 shell 现以 **root** 运行，而 `/data/dsh/北斗/beidou` 属主是 **node:node**。
后果一次实测：仓库内积了 **295 个 root 属主文件**（子代理写入所致，含 91 个源码/文档）。
不立刻报错，但**node 侧将来 `git checkout` / 换分支会被权限拒绝**，且报错不指向真因。

固化：
- **git 一律 `su node -c '<cmd>'`**；权威测试数字**必须 node 身份跑**（root 与 node 结果会不同，见 14.2）。
- 每单收工必须 `find /data/dsh/北斗/beidou -user root | wc -l` → **0**，否则 `chown -R node:node` 后再核。
- 反方向也不要图省事去配 `safe.directory` 让 root 直接操作仓库：root 写 `.git` 会把对象/索引变成 root 所有，
  等于把权限地雷埋给 node 侧。（本轮我拒绝了这条捷径。）
- `验收-批次一.sh` 原为 `600 root`，node 读不到 → 已改 `644`（纯测试脚本，无敏感内容）。

### 14.2 **跳过不能冒充通过**（本轮最值钱的一条）
`test_skill_wire.py` 的 `_git_show()` 原本「`git show` 返回非零即 `pytest.skip`」。
于是 root 身份下 git 报 `detected dubious ownership`（返回 128）→ **2 条守字节用例静默跳过**，
而**跳过不影响退出码**，闸照样 `✅ 266 passed`。**守卫已停止守卫，全系统看不出来。**

固化：
- **跳过必须区分「环境根本不具备」与「本应成功却失败」**。只有前者可 skip：
  无 git 可执行文件、或 `rev-parse` 明确回 `not a git repository`（**只认这个字符串，不认返回码**——
  dubious ownership 同样是 128，看码等于把口子原样留下）。其余一律 `pytest.fail`，message 带 stderr 前 200 字。
- **闸把 skipped 判为失败**：`run()` 解析 pytest 汇总行的 `N skipped`，>0 即该层失败并打印「覆盖已缩水」。
- 普查结论：全仓 `pytest.skip` / `skipif` / `importorskip` / `skipUnless` 除上述一处外**零命中**。
- 同族教训（呼应本仓旧例）：**「存在性断言」与「跳过」是同一类失效的两种外观**——都让判据看起来在、
  实际不咬。判据只有一条：**把生产按 feared 方向改坏，它红不红。**
