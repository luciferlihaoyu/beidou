# 平台合规检测：口径来源与边界

> 这份文档记录 `backend/app/censor.py` 里分级规则**从哪来**、**能保证什么**、
> **不能保证什么**。改词表前请先读这里。

## 一句话边界

**各平台的确切屏蔽词库是内部机密且动态更新，任何外部词表都不可能完整或实时。**

所以本系统不做、也不该做「敏感词清零即合规」的承诺。它做的是：

1. 把**可确定的**风险信号挑出来，按公开审核口径分三档处置；
2. 每档给出**合规改写方向**（不是「换成另一个词躲过去」）；
3. 明确标注哪些项**需要人工结合语境判断**。

平台官方自己也这么表述：不存在「敏感词清零即合规」，必须结合意图、细节程度、
可复现性、对象和后果判断。

## 分级口径

| 级别 | 含义 | 处理 |
|---|---|---|
| 🔴 block 硬红线 | 法律法规/暴恐极端/淫秽色情/赌博吸毒/教唆犯罪/未成年不当/邪教与迷信现实宣传/隐私人肉 | 必须删改，不要试图软化成同义词 |
| 🟠 fix 影响审核或推荐 | 引流联系方式、正文里的作者话、广告交易、乱码占位、重复填充、水文特征、涉黑违法 | 高概率影响审核或推荐，建议改 |
| 🔵 review 需结合语境 | 暴力细节、擦边描写、现实品牌、现实原型、脏话、绕审写法 | 人工判断，不自动判定违规 |

**核心判定原则**：区分「虚构出现」与「宣扬 / 教学 / 号召」。
灵异、反派犯罪、战斗冲突可以作为剧情元素；一旦变成现实可复现的教程、
价值鼓励或模仿诱导，即升级为红线。

**平台差异**：同一处证据在不同平台等级不同（`PLATFORM_PROFILES[*]["escalate"]`）。
例如「分尸」在通用口径是 review，在番茄升为 fix。

## 我们**不做**的事

- 不提供「绕过审核的写法」——包括替换表、拆字/谐音/符号间隔教程。
  平台**明确禁止**为躲审故意写不规范，本检测把这类写法本身标为 review 项提示作者。
- 不声称某一段就是平台拒审原因（没有平台具体拒审理由时不下结论）。
- 不保证过审或推荐结果。

## 词表怎么维护

- 词表在 `backend/app/censor.py`：`RULES`（类别 → 词）、`PATTERNS`（可检测模式）、
  `SAFE_COMPOUNDS`（误报白名单）、`CATEGORY_META`（每类的 why/how）。
- 平台加严在 `backend/app/textlint.py`：`PLATFORM_PROFILES`。
- **加词前先想误报**：短词要进 `SAFE_COMPOUNDS`（已有例：「大麻烦」含「大麻」、
  「下体育课」含「下体」、「骏马奔驰」含「奔驰」）。
- `backend/tests/test_censor.py` 会强制校验：类别名一致、同词不跨类别重复、
  白名单引用真实词、平台加严类别有效、词表规模下限。改词表后必须跑它。
